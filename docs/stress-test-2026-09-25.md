# Chatbot scenario stress test — 2026-09-25

Fourteen new scripted customer conversations (59 turns) were run through the
live `/query` endpoint, classified, compared with what market-leading
support agents do, and used to drive fixes. Verbatim transcripts:

- before: [stress-test-2026-09-25-transcripts-before.md](stress-test-2026-09-25-transcripts-before.md)
- after: [stress-test-2026-09-25-transcripts-after.md](stress-test-2026-09-25-transcripts-after.md)

The scenarios live in `src/tests/scenarios/11_*.json` … `24_*.json`
(generated by `_write_live_scenarios.py`) and the driver is
`src/tests/run_live.py`. Every expected outcome was written before the
first run and was not changed afterwards.

## How it was run, and the caveats

- **Provider.** `src/.env` has `PROVIDER_ROLE_DEFAULT=deepseek` (V4 Flash,
  thinking disabled) and `PROVIDER_ROLE_ADVANCED=openai` pointed at the
  on-prem LiteLLM gateway, which was **NXDOMAIN again** (`nslookup`:
  non-existent domain). DeepSeek answered (`/models` 200), so every
  transcript below is a real model answer, not routing-only. The
  `advanced` role paid one failed connect before falling to DeepSeek on
  the first such question; the provider cooldown then skipped it.
- **Backend.** `preview_start` is refused in unattended sessions. The
  backends already running were stale (`:8000` since 2026-09-24 16:26,
  `:8001` since 07:10, both before today's commits), and four attempts to
  start a fresh one died seconds after warm-up with an `RPCRT4.dll`
  access violation logged by Windows Error Reporting (no Python
  traceback). What survived: `nohup python -X faulthandler -m uvicorn` on
  `:8004`, readiness read from its log. The "before" run therefore used
  the 07:10 `:8001` backend (commit `78f08a2`; HEAD minus the four
  behaviour-neutral refactor/cleanup commits of 07:36–07:44), the "after"
  runs used `:8004` on the patched tree. No corpus re-ingest; the index
  is the shared `src/chroma_db`.
- **Scoring.** `run_live.py` is a shape check, not a grader: it reads the
  observed outcome (`answer / refuse / deflect / clarify / manual /
  handoff`) off the response and checks `mention` / `avoid` words. "Pass"
  means "the shape a support engineer expected, with the words they
  expected"; it does not certify every fact. Two scorer fixes were made
  after the first run (the friendly refusal cites pages, and the
  document route has role `document`); the baseline below is re-scored
  with the final scorer so before/after are like for like.
- **Noise.** DeepSeek at temperature 0 is not deterministic here: the same
  resolved question was refused in one run and answered in the next
  (11 T5, 12 T1, 13 T4, 18 T1, 19 T2/T3 each flipped at least once across
  four runs). Single-run deltas of one or two turns are within that noise;
  the deltas claimed below are the ones that reproduced.

## Gap analysis against market leaders (Intercom Fin, Zendesk AI agents, Ada, Forethought, Sierra, Decagon)

Ranked by customer impact. "Achievable" means in this codebase with a
cloud or local model of DeepSeek-Flash class.

1. **Handoff to a human / ticket creation.** Leaders detect "talk to a
   person" and open a ticket with the transcript attached. Here it was a
   clarify (19 T4, 21 T3/T4). **Achievable, done today**: `intents.py`
   recognises the request, the turn returns `role: handoff` +
   `offer_support`, and the widget's existing support form (`/widget/lead`,
   which already carries the transcript into the console's Leads page) is
   the ticket. Still missing: a ticket ID shown to the visitor, and any
   push into an external desk (email/Jira/Zendesk) — a new module.
2. **Answer consistency.** Leaders retry or ensemble so the same question
   gets the same answer. Here the same resolved question was refused and
   answered on different runs (see Noise). **Partly achievable, partly
   done**: a refusal on a follow-up with confident retrieval is now
   retried once without the `<conversation>` block (16 T6, 11 T5, 23 T3
   recovered). Full determinism is out of reach with a sampled model; a
   second retry costs ~1s per refusal.
3. **Comparison questions.** Leaders answer "X vs Y" from two documents.
   Here the multi-product gate asked "which did you mean?" with both
   named (18, 14 T2). **Gate fixed today** (`_COMPARISON` covers "which
   one", "both", "the same", "faster … or"); what remains is the model
   declining to synthesise two specs into one sentence (18 T2/T3 after
   the fix). A dedicated comparison prompt that presents the two products'
   passages side by side is a small new path (~80 lines) and is the next
   thing to try; not done today.
4. **Multi-turn context.** Leaders track entity switches. Condense already
   has the rule, but it lost the switch once (14 T3, before) and the
   "step 3" follow-up re-served the whole procedure (13 T2). Product
   switch **fixed via the comparison gate** (14 now 4/4). "Step N" needs
   the previous answer's numbered list, not retrieval — achievable with
   `_expand_previous`-style logic on `is_more_request`; not done.
5. **Document requests.** Leaders return the file. T1 worked; follow-ups
   and second documents did not (17). **Done today**: trailing "too / as
   well", "checklist" as a noun, and a bare document name straight after a
   document list.
6. **Commercial questions.** Leaders route to sales with lead capture.
   Price/quote/discount/lead time already deflected in <1s (16). Warranty
   did not (15 T1). **Done today** (`warranty`, noun `guarantee`). Still
   English-only: "Quel est le prix" is answered in French by the model
   (24 T3). A multilingual commercial regex is small; a proper fix is item 9.
7. **Tone and small talk.** Leaders greet and close naturally. "hello, how
   are you today" got "I don't have that in the product documentation" and
   three FAQ links (22 T1). **Done today** for bare greetings; "thank you"
   was already handled by the model (20 T4). Refusal prose is still stiff
   ("I could not pin down …" quoting the visitor's own typo back at them,
   20 T3) — a copy change, not made.
8. **Grounding on absence.** "Does the MyCheckr support Bluetooth" → "No."
   with grounding 0.002 and no flag (15 T2): the manual lists USB and
   Ethernet, never Bluetooth. Leaders would say the same, and be equally
   unsupported. This is the inference contract's territory
   (`grounding.check_inference`, off by default) — **achievable but
   deliberately not switched on**; the honest answer today is "the manual
   does not mention Bluetooth", which no path produces.
9. **Multilingual.** Leaders answer in 40+ languages. Spanish and German
   questions are refused at the retrieval gate (24 T1/T2) because
   retrieval is English-only; the model itself will answer in French when
   retrieval happens to pass. **Achievable, not done**: run the condense
   step on a first turn when the text is non-English with "rewrite in
   English", retrieve in English, and add "answer in the language of the
   question" to the answer prompt. Two prompt changes plus one extra model
   call on non-English turns; not measured today.
10. **Proactive suggestions.** Leaders suggest next questions. The FAQ
    candidate menu and `suggested_replies` exist and fired (23 T3 before);
    they are offered instead of an answer rather than alongside one. Not
    changed.
11. **Analytics / feedback loop.** The console has a gap list
    (`/faq/gaps`, dedup + auto-resolve), the pipeline trace and the Leads
    page; there is no per-answer thumbs up/down from the widget, so
    "answered but wrong" is invisible unless a visitor writes in. A
    `/widget/feedback` endpoint plus two chips is small; not done.
12. **Taking actions.** Leaders can look up an order or reset a device.
    Nothing here acts on anything; the only "action" is the lead form. Out
    of reach without integrations, and out of scope for a manuals bot.
13. **Latency.** Median 3.9s per turn, answers ~5s, deflects/handoffs
    <1s; leaders stream at 2–4s. `/query/stream` exists; the harness used
    `/query`. Acceptable; not changed.

### Routing labels on the new scenarios

`run_scenarios.py` now scores 24 files. The original ten stay 79/79. Of
the 18 disagreements on 11–24, all are `followup` labels: the classifier
calls "how do I connect it to my machine", "how do I clear that", "tried
all that, still offline" standalone. In the live runs those turns were
resolved correctly by the condense step regardless, so the flag only
bites when generation then refuses. Left as written — the labels are the
engineer's reading and the runner exists to show where the code disagrees.

## Left undone, and why

- Comparison synthesis prompt (item 3) and "step N" from the previous
  answer (item 4): each is a new path rather than a rule change; the
  evidence is in 18 T2/T3 and 13 T2.
- Multilingual (item 9): two prompt changes plus a detection heuristic and
  a model call; needs its own measurement run.
- Widget feedback chips (item 11) and a visible ticket ID on handoff
  (item 1): small, but UI work outside what these transcripts measure.
- "Bluetooth: No." (item 8): a policy decision on the inference contract,
  not a bug fix.
- The RPCRT4 crash of freshly started backends: reproduced four times,
  cause not found (the `session-tooling-gotchas` memory notes torch must
  first import on the main thread, which today's "models imported on
  first use" commit may have changed). The recipe that works is recorded;
  the crash itself is filed in PENDING.
