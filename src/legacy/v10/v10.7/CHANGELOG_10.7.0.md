## Why your MyCheckr / General chats returned "which product?"
Your 3 docs (270 chunks) were ingested via the PLAIN Documents dialog,
which does NOT tag category/product. So every chunk has category=""
product="". A MyCheckr chat scopes to product=mycheckr -> matches ZERO
chunks -> "which product?" clarify. Same reason: no FAQ chips (entries
recorded with empty tags), general chat empty.

The docs are fine and ingested — they're just UNASSIGNED. Fixed without
re-ingesting:

## 1. NEW: assign-documents tool in the admin panel
Admin panel now lists every ingested document with its current tag
(shows "untagged" in orange for yours). Each has an "Assign to…"
dropdown (Category › Product). Pick one and it re-tags that doc's chunks
in place (no re-embed, uses the /admin/reassign_source endpoint from
10.5). This is how you fix your current 3 docs:
  Admin -> "Ingested documents" section ->
    MyCheckr User Manual-v7  -> assign to Biometrics › MyCheckr
    MyCheckr Mini Manual-v5  -> assign to Biometrics › MyCheckr Mini
    MyConnect Environment-v4 -> assign to Biometrics › General (shared)
After assigning, the MyCheckr chat answers and FAQ chips appear.

## 2. "General" product now in EVERY category
Biometrics was missing a General product (only had MyCheckr/Mini/
MyConnect). Now every category — including new ones you create — gets a
"General (shared docs)" product. Attach shared docs (like MyConnect/API
docs) there; a category-level chat sees them across all products.
NOTE: if catalog_config.json already exists on your volume, the new seed
won't apply automatically — either add a "General" product via the admin
"Add product" form (key e.g. biometrics_general), or delete
catalog_config.json to re-seed.

## 3. Docs now show their assignment
The assign list shows each doc's current "Category › Product" tag, so you
can see what's attached where (was invisible before).

Chips need FAQ entries, generated by doc2query AT INGEST. Your docs may
