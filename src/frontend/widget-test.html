Launcher appears bottom-right. Ask something answerable from the ingested corpus, e.g. “How do I set up RNDIS between an ICU device and a local Ethernet adapter in Linux?”

Backend

/api is the same-origin nginx/Vite proxy, so the browser needs no CORS — this is the path that works today. Using http://localhost:8000 instead exercises the real cross-origin embed, which currently fails: the backend has no CORS middleware (add_cors.patch is unapplied), so the browser blocks the response.

What this harness is

A throwaway page for local testing. It sits at the frontend root so Vite treats it as an HTML entry and serves it at /widget-test.html (HTML in public/ is not served as an entry). It loads the widget from /widget/groundedops-widget.js.

The widget ships in public/widget/, so that URL is the same in dev and in the built nginx image — and because Vite copies public/ verbatim, the file is actually present in dist/. This harness is dev-only: it is not listed as a build input, so it is not emitted.
